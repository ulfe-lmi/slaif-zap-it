# OAP communication protocol — strategic OpenCode

GitHub is remote software truth; OAP files orchestration truth; FIFOs sync only.
Payload exactly bytes `OK`. Strategic publishes immutable order and `oap/active`,
sends control, blocks on response, reads immutable report, independently verifies
GitHub, and decides. Coding never merges.

ID `NNN-L`: `a` creates one new PR; `b..z` same branch/PR. No next numeric order
until accepted merge and remote-main verification. No `aa`; escalate at `z`.

## Decision duty and deferred human adjudication

Strategic must not stop the autonomous loop merely because it does not want to
own a consequential choice. First exhaust applicable human intent, architecture,
order, evidence, alternatives and mitigations; then make the best provisional
decision. Immediate human escalation is reserved for missing human-exclusive
facts/authority or an imminent non-delegable production/public/destructive/release
action—not ordinary uncertainty.

Use `CRITICAL.md` only for rare dilemmas meeting every one of its five threshold
conditions. When warranted, author exact `CRIT-NNNN` bytes, include them in the
same objective order (or next letter after review discovery), and require coding
to append them with `append_critical.py`. Verify no earlier register bytes changed.
Do not create a new numeric objective solely to record the entry. Do not add an
entry merely to reduce strategic reasoning burden.

Open entries permit continued development/merge only when the provisional design
is bounded and safe. They block the stated human gate. Agents never append human
adjudications or declare the gate closed; only the latest human `ACCEPTED`
disposition clears it.

## Cycle

1. Refresh constitutions/architecture/roadmap/prior evidence.
2. Query GitHub default SHA, open/recent objective PRs, checks/reviews/mergeability.
3. Query relevant host facts: tests/tooling, all GPUs/processes, the
   active-order-assigned physical index/UUID/VRAM, unassigned-device protection,
   `/dev/shm`, listeners, environment/service state.
4. Choose new objective or next same-PR letter; resolve material ambiguity.
5. Apply the `CRITICAL.md` five-condition test. Normally record `NONE`; if all
   conditions hold, make the decision and include exact append-only entry bytes.
6. Write complete strategic-local order; remove all draft/verify markers.
7. Publish with `publish_order.py`; then send exact control `OK`.
8. Block on response FIFO.
9. Require same active ID and one report; extract PR/SHA/SELF/tests/GPU/service/
   critical-register action.
10. Independently verify PR identity/base/head/diff/commits, SELF one-path commit
    and parent, current checks, scope/security/docs/live evidence, and any ordered
    append-only `CRIT-NNNN` bytes.
11. Merge iff development gates pass; otherwise wait or issue exact next letter.
    Preserve every applicable human deployment/release gate.

Crash/restart: recover from active/order/report/GitHub. If coding crashed after
consuming signal and no final report exists, restart coding wrapper and re-send
control for the same unresolved order; do not create a new letter solely for
process failure. Existing reports are immutable.

Every order states objective, verified GitHub state and PR mode, bounded scope/
non-goals, requirements/criteria, exact CPU/API/GPU/CI evidence, docs/provenance,
security/resource/GPU0 constraints, publication/report contract, and a
`Deferred human adjudication: NONE | APPEND CRIT-NNNN` section. `NONE` needs no
boilerplate rationale. `APPEND` requires exact entry bytes and proof that all five
threshold conditions hold. Routine setup belongs to coding; strategic decides
provisional design while the human retains non-delegable deployment/release
authority.
